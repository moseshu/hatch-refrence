# P3 多轮评估

## Linux 脚本评估

下面的 15 世界回归以 P3 交付提交 `90141e3` 为准。比较基线和候选时使用同版 P3 评估工具，以及相同的日期、夹具和运行参数。浏览器世界需要可运行的 Chromium，命令世界需要来宾系统允许 Hatch 使用用户与挂载命名空间。首轮流水线只调用脚本模型。

```bash
cargo test --locked -p hatch-eval -p hatch-cli --lib --bins
cargo build --locked -p hatch-cli
hatch_bin="$PWD/target/debug/hatch"
umask 077
batch=$(mktemp -d "${TMPDIR:-/tmp}/hatch-p3.XXXXXXXX")
export HATCH_EVAL_TODAY=2026-11-28
export HATCH_EVAL_LEDGER="$batch/ledger"

for world in eval/worlds/*; do
    [ -f "$world/capabilities.json" ] || continue
    name=${world##*/}
    "$hatch_bin" eval --world "$world" --repeat 2 --out "$batch/runs/$name" ||
        printf '查看运行结果 %s\n' "$name" >&2
done
"$hatch_bin" eval-scorecard "$batch"/runs/* --out "$batch/scorecard.md"
jq -es 'length == 15 and all(.status == "completed" and (.rounds | length) == 2)' \
    "$batch"/runs/*/run.json
```

`round-N/` 保留各轮独立清单、完整报告和轨迹。外层 `report.json` 按检查统计通过、失败、证据不足和缺失，分母包括中断轮。单项通过率以有判定的轮次为分母，范围只表示各轮是否出现过通过和失败。比较整体波动时查看配对报告的 `round_delta_range`。外层 `run.json` 汇总已有判定和各轮调用量。失败类别属于规则初判，逐轮清单中的 `failures` 包含依据和待人工复核标志。缺乏终止证据时，质量失败的初判需要优先复核。

开发集台账也可用 `--ledger` 指定固定目录。配置了 `HATCH_EVAL_LEDGER` 时，带 `--out` 的开发集运行自动登记。每次启动生成一个条目，正常退出和返回错误时更新状态并链接同一运行 ID 的清单。夹具或配置加载失败时，条目保留阶段和错误。进程被强制终止时，条目保持 `running`，可通过输出目录查找已完成的逐轮清单。配置 `--attempt` 可把预登记的假设、改动和预期影响带入台账。

```json
{
  "hypothesis": "回读后的独立检查可以减少误报",
  "change": "在候选版本追加独立回读",
  "expected_impact": "提高 C9 并保持关键动作检查全部通过",
  "reproduction_id": "dev-readback-01"
}
```

留出集忽略开发集的 `HATCH_EVAL_LEDGER`。独立评估方在私有目录显式传入 `--out` 和 `--ledger`，并按计划只导出汇总。

## 同题配对

从同一个包含 P3 工具的提交建立两个工作树。在基线工作树中，用配置开关或最小补丁恢复待评估改动之前的 harness 行为。在候选工作树中启用该改动。两边都用同版 P3 运行器、清单格式、夹具和评分器，并在各自目录构建和执行。若必须从早期提交取基线，先将同版 P3 评估工具回移到该提交，再重新运行。P3 之前生成的多轮报告缺少逐轮清单，无法用于配对。

```bash
"$hatch_bin" eval --world eval/worlds/web-live --repeat 2 --out "$batch/web-again"
"$hatch_bin" eval-compare --baseline "$batch/runs/web-live" \
    --candidate "$batch/web-again" --out "$batch/paired.json"
jq -e '.counts.both_pass == 12 and .round_delta_range == [0, 0]' "$batch/paired.json"
```

配对按任务和轮次计数，并给出各能力的转移计数。作废轮和证据不足独立计数。亦可查每轮原始 token 和成本字段，未计价的成本为 `null`。配对需要相同夹具、评分规则、模型配置和预算。运行日期可通过 `HATCH_EVAL_TODAY` 固定，对照双方使用同一个值。双轮汇总记分卡接收外层运行目录。

真模型矩阵为每个模型使用单独的配置和调用预算，记录实际模型、供应商、路由、版本和用量。在同一版本的运行目录上使用 `eval-scorecard --by-model` 查看各能力的并列表。每列显示请求、计分和中断或作废的轮数。能力行以请求的任务轮次数为分母，并单列证据不足和作废数。每个模型先小试并按实际计价估算预算。正式对照前在台账登记最小改善、可接受回归、关键检查和不确定性判定规则。配对工具提供原始计数和观察波动范围，正式改善与持平由登记的规则判定。

## 差异复现与评分器锚点

`eval-replay` 接收开发集的单轮运行目录。先用回放定位首个差异，再给开发集案例填写经人工确认的失败类别、稳定错误特征和最小复现编号。相同机制的独立回放可以关联同一个复现。归组文件中的相对路径以该文件所在目录为基准。

```json
[
  {
    "case_id": "dev-readback-a",
    "diff": "replay-a/diff.json",
    "kind": "quality",
    "signature": "changed-tool-readback",
    "reproduction_id": "dev-readback-01"
  }
]
```

`hatch eval-group --cases cases.json --out groups.json` 按首个差异阶段、类别和稳定特征生成组 ID 与出现次数。组 ID 和复现编号可以写入后续台账的尝试记录。

`hatch eval-calibrate --anchors anchors.json --out calibration.json` 接受一个组件的人工类别、观察输出以及对照预测，汇报各类命中数、分母和违反项。若出现登记为禁止的违反项，当前锚点计错。组件命中数须严格超过每个退化对照。正式锚点和人为判定由独立评估方保管。

```json
{
  "component": "l3-grader",
  "controls": ["always-pass", "always-fail"],
  "forbidden_violations": ["wrong-citation"],
  "anchors": [
    {
      "id": "anchor-01",
      "expected": "fail",
      "observed": "fail",
      "controls": {"always-pass": "pass", "always-fail": "fail"},
      "violations": []
    }
  ]
}
```
