# scheduler-basic 评估世界

用**假时钟**驱动调度器与后台 worker，在毫秒内走完多天：

| 场景 | 检查什么 |
|---|---|
| DST 秋季回拨（纽约，`daily 01:30`，10-30 → 11-03） | 每天恰好一次，11-01 重复的 01:30 只触发第一次 |
| DST 春季跳时（纽约，`daily 02:30`，03-07 → 03-10） | 不存在的 02:30 顺延到 03:00 |
| daemon 停机 5 小时（`every 30m`） | 记录错过 10 次；`catch_up = none` 不补跑，`once` 只补跑一次；之后按计划恢复 |
| 连续失败 | 退避重试，第 3 次失败后自动禁用并写通知 |
| 卡死的任务 | 看门狗按 `timeout_secs` 停止，记为失败 |
| 停止信号 | 运行中的任务在取消点停下，记为"已取消"，锁释放；下次启动重跑 |
| 每日简报 | 同一天只生成一份；条目必须引用事实；编造条目被丢弃；该提的都提到、不该提的不出现；覆盖缺口由代码写明；无事项时不调用模型 |
| 定时分诊的外发 | 任务范围为空时，即使有匹配的常设授权，回复也进入审批队列；对照组（范围含 `send_message`）同一授权会自动发送 |

pipeline 模式用脚本模型（简报中故意夹带两条无依据的编造条目）；live 模式用真实模型生成简报与分诊，并统计条目文字与所引用事实的重合度。
