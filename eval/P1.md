# P1 评估运行与服务器验收

P1 增加 15 个现有世界的能力标注、统一运行记录、跨世界记分卡、`web-live` 离线差分回放，以及网页资料时效任务的首个生成模板。正式留出包仍由独立评估方保管。Muse 小试使用计划 P5 的共同任务协议，独立报告设备、权限、触发方式和可取证条件。

## Linux 上的确定性验收

在相同提交的仓库根目录执行。浏览器世界需要实际 Chromium 和现有沙箱配置。每次运行使用新目录，从当前构建重新录制回放基线。

```bash
cargo test --workspace --locked --no-fail-fast
cargo build --locked -p hatch-cli
hatch_bin="$PWD/target/debug/hatch"
umask 077
batch_dir=$(mktemp -d "${TMPDIR:-/tmp}/hatch-p1.XXXXXXXX")

for world_dir in eval/worlds/*; do
    [ -f "$world_dir/capabilities.json" ] || continue
    "$hatch_bin" eval --world "$world_dir" --out "$batch_dir/${world_dir##*/}" ||
        printf '查看运行结果 %s\n' "$world_dir" >&2
done
"$hatch_bin" eval-scorecard "$batch_dir"/*/ --out "$batch_dir/scorecard.md"
jq -es 'length == 15 and all(.status == "completed" and (.rounds | length > 0))' \
    "$batch_dir"/*/run.json
rg -F '未标注检查 0 · 缺失检查 0' "$batch_dir/scorecard.md"
rg -F '无检查任务 1 ·' "$batch_dir/scorecard.md"
```

核对每个运行目录的 `run.json` 和 `report.json`。未通过业务检查时仍保留报告，提前退出使用 `interrupted` 状态。有模型调用的世界会写入 `model-trace.json` 以及按摘要去重的 `model-contexts/`，其中可见角色、工具描述和参数、模型响应及返回给模型的工具结果。图片只保存类型和内容摘要。审批记录和独立业务验收沿用各世界报告。旧记忆报告保留原有轨迹和召回字段。统一清单使用版本 2，`provider_usage` 按轨迹统计每次已发起的模型请求，包含重试、失败与夜间记忆提取。用量对账使用这个字段。记忆世界原有的 `usage` 和 `extract_usage` 保留供专项诊断，二者已覆盖在 `provider_usage` 中。每轮保留题目、检查和调用量的不同分母，已知覆盖不足的能力显示题量差。金额留空，待按实际供应商计费估算。

验收要求 15 个世界均生成报告，记分卡的**未标注检查和缺失检查均为 0**。题数按当前模式下有检查的任务 ID 去重，预期另有 1 个无检查任务（`memory-crossday/d2-todo`）。世界级检查按能力标签和轮次统计通过、失败和缺失，题量独立计算。用记分卡排序时，检查各能力行的世界级失败列，包括 C10。记分卡每次接受同一运行模式、提交和留出状态的结果。同一世界的重复运行使用同一夹具和设置。检查没有证据时标为无法判定。范围内全部必需检查通过才算该题在该能力通过。独立评估方可给私有留出包附上 `capabilities.json`，在私有目录生成记分卡。开发侧仅收汇总。

### 离线重放和种子变体

```bash
"$hatch_bin" eval-replay --baseline "$batch_dir/web-live" --out "$batch_dir/replay"
"$hatch_bin" eval-replay --baseline "$batch_dir/web-live" --out "$batch_dir/replay-repeat"
cmp "$batch_dir/replay/diff.json" "$batch_dir/replay-repeat/diff.json"
jq -e '.observed_stage == "identical" and .incomparable_from_request == null' "$batch_dir/replay/diff.json"

"$hatch_bin" eval-variant --seed 42 --out "$batch_dir/variant-a"
"$hatch_bin" eval-variant --seed 42 --out "$batch_dir/variant-b"
"$hatch_bin" eval-variant --seed 43 --out "$batch_dir/variant-c"
cmp "$batch_dir/variant-a/variant.json" "$batch_dir/variant-b/variant.json"
"$hatch_bin" eval --world "$batch_dir/variant-a/world" --out "$batch_dir/generated-run"
"$hatch_bin" eval-scorecard "$batch_dir/web-live" "$batch_dir/generated-run" \
    --out "$batch_dir/variant-scorecard.md"
rg -F '去重任务 6 · 表层变体 1' "$batch_dir/variant-scorecard.md"
```

回放使用基线的脚本响应、夹具指纹和模拟时钟，网页和外部状态均来自本地夹具。请求无法匹配时，报告首次差异及后续不可比较的起点。版本间比较前，用 `--expect-stage` 登记预期的首个差异阶段，缺省预期为一致。同一构建的重放结果应为 `identical`。全链路测试从 `web-live` 录制基线，回放时仅改第一次网页抓取返回给模型的正文，保持夹具指纹不变，预期首个差异为第 2 次请求的 `readback`。种子生成的包标为 `surface`，改变离线版本值、记录编号和任务 ID，沿用原题的操作路径。记分卡单列结果，题量目标按非表层任务计算。

## 首批真模型小试

先跑确定性验收。然后在服务器上用同一个已配置的模型和同一个提交，各跑一轮下面的开发集。它们合计 15 个任务，覆盖三种不同的证据来源。按计划预算观察实际用量，达暂停线时停止下一批。

| 世界 | 为什么需要真模型 | 重点核对 |
| --- | --- | --- |
| `tool-faults` | 真实模型需要自己判断重试、回读和停止时机 | 丢失写入回执后先回读，无重复写入。真实请求和用量已记录 |
| `memory-pressure` | 真实模型需要按检索证据使用已保存偏好 | 同一轮的目标、评估结果、上下文与调用量可对齐 |
| `web-live` | 需要测真实网络取证、最新值和死链处理 | 网络记录无 TLS 握手失败，引用已读取来源，真实模型用量与诊断可核对 |

```bash
live_dir=$(mktemp -d "${TMPDIR:-/tmp}/hatch-p1-live.XXXXXXXX")
"$hatch_bin" eval --world eval/worlds/tool-faults --live --max-calls 40 --out "$live_dir/faults"
"$hatch_bin" eval --world eval/worlds/memory-pressure --live --recall auto --max-calls 40 --out "$live_dir/memory"
"$hatch_bin" eval --world eval/worlds/web-live --live --max-calls 40 --out "$live_dir/web"
"$hatch_bin" eval-scorecard "$live_dir"/*/ --out "$live_dir/scorecard.md"
```

三份真模型结果都应有非空的 `model-trace.json`。下面把轨迹行数、输入和输出 token 与统一清单对账，并按路由器分别核对预算。记忆提取通过独立路由器运行，使用自己的预算。无成功回复的尝试也计入调用量。路由器拒绝的超额请求未发往模型。

```bash
for scenario in faults memory web; do
    run_dir="$live_dir/$scenario"
    jq -e --slurpfile run "$run_dir/run.json" '
      . as $trace | $run[0] as $manifest
      | $manifest.provider_usage as $usage
      | (length > 0)
        and (length == $usage.calls)
        and ([.[] | .response.usage.prompt_tokens // 0] | add) == $usage.prompt_tokens
        and ([.[] | .response.usage.completion_tokens // 0] | add) == $usage.completion_tokens
        and ($trace | any(.router_id == 1 and .router_call_limit == $manifest.settings.max_calls))
        and (group_by(.router_id) | all(
          (map(.router_call_limit) | unique | length) == 1
          and (.[0].router_call_limit == null or length <= .[0].router_call_limit)
        ))
    ' "$run_dir/model-trace.json" || exit 1
done
```

记录实际模型、各路由器的调用上限、token、完整检查数，以及网络或预算原因。只有评估接线、记分卡、生成器和脚本回放的验收可以依赖确定性结果。真模型单轮用于确认记录完整和观察行为，后续多模型配对按 P3，正式留出按独立协议。
